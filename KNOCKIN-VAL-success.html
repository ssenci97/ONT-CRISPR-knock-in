Inputs and parameters

What each input is, which step reads it, and how every variable in configs/param_configs.yaml maps to the original tool arguments. Values are the current ones; each analysis freezes its own copy in results/<analysis>/inputs/params.yaml.

Input data types

  • FASTQ (local)gzipped FASTQ (.fastq.gz), one file per sample, absolute path on the cluster

    The preferred source. Step 01_fetch length-filters it with seqkit into results/<analysis>/data/<sample_id>.fastq.gz; the original file is never modified. Directories outside the repo are bound into the container automatically by the driver (src/pipeline.py).

  • SRA run accessionSRR / ERR / DRR followed by digits

    The alternative source, for public data. Step 01_fetch checks the read count against ENA, downloads the .sra file, converts it with fasterq-dump and keeps it in the shared cache data/raw/<run>.fastq.gz, so later analyses reuse it.

  • sample_idletters, digits, underscore

    The row key. It names every file, log and SLURM job of the sample, so it must be unique within the sheet.

  • conditionfree text

    A human-readable label for the treatment, e.g. rnp_dsDNA_donor. Carried into summary.tsv and the KI % matrix; not interpreted by the tools.

  • controltick box (1 / 0)

    Marks a negative control. The first ticked sample is passed to CRISPRLungo as --control; at least one is required.

  • Wet-lab and sequencing fieldsfree text, dates, numbers

    Provenance only. Stored in configs/samples/<sample_id>.json and copied into results/<analysis>/meta/; never read by the tools.

  • References (built by 02_refs)TRAC_WT.fa, TRAC_KI.fa, CAR_insert.fa, alpine/ref.fa, alpine/config.tsv, design.json

    Control (unedited) and knock-in amplicons, the inserted gene, guide, primers and homology arms. Built from a genome window (refs.region) and the donor template table of the paper (refs.pmc). The files are named after the example locus (TRAC, CAR); their roles are the same for any target.

Variables

  • shared.ki_min_insert_frac=0.8

    Minimum fraction of the inserted gene that a read must cover to be counted as a knock-in. 0.8 means at least 80% of the insert must be present; shorter, truncated integrations are not counted. The same threshold is applied to both tools so their percentages are comparable.

    Step: 03_alpine, 05_summary · Original argument: ALPINE truncated_cutoff in job.yaml; for CRISPRLungo it is applied afterwards by summarize.py on the merged insert blocks

  • fetch.bioproject=PRJNA1257358

    NCBI/ENA BioProject that the SRA runs belong to. Only used to download the run table from ENA, so that every downloaded run can be checked against its expected read count. Not needed when all samples are local FASTQ files.

    Step: 01_fetch (ena, download) · Original argument: ENA filereport accession=

  • fetch.min_len=3500

    Shortest read kept, in bp. Reads below this length are dropped before any tool sees them (primer dimers, broken reads). Nothing is subsampled: all passing reads are used.

    Step: 01_fetch (filter) · Original argument: seqkit seq -m

  • fetch.max_len=7500

    Longest read kept, in bp. Removes concatemers and chimeric reads much longer than the knock-in amplicon.

    Step: 01_fetch (filter) · Original argument: seqkit seq -M

  • refs.region=14:22540000..22560000:1

    hg38 genomic window (chromosome:start..end:strand) that contains the amplicon. Downloaded once from Ensembl and pinned by sha256.

    Step: 02_refs · Original argument: Ensembl REST /sequence/region/human/<region>

  • refs.pmc=PMC12166421

    Europe PMC id of the paper whose supplementary table holds the HDR donor templates. Downloaded once and pinned by sha256.

    Step: 02_refs · Original argument: Europe PMC supplementaryFiles

  • build_refs.genomic_fasta=data/raw_refs/hg38_chr14_22540000_22560000.fa

    Local path of the cached hg38 window downloaded from refs.region.

    Step: 02_refs · Original argument: build_refs.py --yaml-in

  • build_refs.genomic_start_1based=22540000

    1-based genomic coordinate of the first base of genomic_fasta; converts positions in the window back to hg38 coordinates.

    Step: 02_refs · Original argument: build_refs.py --yaml-in

  • build_refs.templates_xlsx=data/raw_refs/supp/mmc2.xlsx

    Supplementary spreadsheet containing the donor templates (full sequence and homology arms).

    Step: 02_refs · Original argument: build_refs.py --yaml-in

  • build_refs.template_title=TRAC CD19-CAR HDR template for editing with AsCas12a

    Exact title of the row in the supplementary table to use as donor; selects the knock-in construct.

    Step: 02_refs · Original argument: build_refs.py --yaml-in

  • build_refs.guide=GAGTCTCTCAGCTGGTACACGGC

    crRNA spacer sequence (5'->3'). Locates the cut site in the wild-type amplicon and is passed to CRISPRLungo.

    Step: 02_refs, 04_lungo · Original argument: CRISPRlungo positional <guide>

  • build_refs.cut_offset_from_guide_5p=18

    Distance of the cut from the 5' end of the guide: 17 for SpCas9, 18 for AsCas12a. Wrong values shift the expected integration site.

    Step: 02_refs · Original argument: build_refs.py --yaml-in

  • build_refs.primer_f_full / primer_r_full=TTTCTGTTGGTGCTGATATTGCTTCAATCACTGCTGTGTCCCT / ACTTGCCTGTCGCTCTATCTTCTCCCACCCCAGACCTCCTAGTT

    Full PCR primers including adapters; define the amplicon ends that ALPINE searches for in each read.

    Step: 02_refs, 03_alpine · Original argument: ALPINE primer_1 / primer_2 in job.yaml

  • build_refs.primer_f_specific / primer_r_specific=TTCAATCACTGCTGTGTCCCT / TCCCACCCCAGACCTCCTAGTT

    Gene-specific part of the primers only; used to locate the amplicon in the hg38 window.

    Step: 02_refs · Original argument: build_refs.py --yaml-in

  • alpine.primer_check_length=150

    Number of bases at each read end in which ALPINE looks for the primers. Reads whose primers are not found there are discarded as incomplete amplicons.

    Step: 03_alpine · Original argument: ALPINE primer_check_length in job.yaml

  • alpine.data_type=nanopore

    Read technology. nanopore tells ALPINE to expect ONT errors and also makes the pipeline patch ALPINE's hard-coded minimap2 -ax map-hifi into map-ont.

    Step: 03_alpine · Original argument: ALPINE data_type in job.yaml

  • lungo.cleavage_pos=17

    Position of the cut inside the guide as CRISPRLungo counts it; centres the window where edits are scored.

    Step: 04_lungo · Original argument: CRISPRlungo --cleavage_pos

  • lungo.window=25

    Half-width in bp around the cut in which CRISPRLungo scores indels and integrations. Larger values catch more distal edits but also more sequencing noise.

    Step: 04_lungo · Original argument: CRISPRlungo --window

  • threads, mem_mb, runtime

    CPU, memory (MB) and time (minutes) of each job, set in src/pipeline.py. get_best_node uses them to choose a partition and node with enough free resources when each job is submitted.

    Step: every step · Original argument: sbatch --cpus-per-task, --mem, -t; CRISPRlungo -t; ALPINE coresMin/ramMin

Original command lines

01_fetch · seqkit

seqkit seq -j <threads> -g -G - -m <fetch.min_len> -M <fetch.max_len> <raw.fastq.gz> -o data/<sample_id>.fastq.gz

01_fetch · fasterq-dump

fasterq-dump -e <threads> -t <tmp> -O data/raw <run>.sra

03_alpine · ALPINE (cwltool)

cwltool --no-container aav_per_sample_workflow.cwl job.yaml   # job.yaml: fastqfile, reffile, config, sample_name, primer_1, primer_2, primer_check_length, data_type, truncated_cutoff, five_prime_HA_seq, three_prime_HA_seq

04_lungo · CRISPRLungo

CRISPRlungo TRAC_WT.fa <sample.fastq.gz> <out> <guide> --cleavage_pos <lungo.cleavage_pos> --window <lungo.window> --control <control.fastq.gz> --induced_sequence_path TRAC_KI.fa --integration_file CAR_insert.fa -t <threads>

05_summary · summarize.py

python3 src/summarize.py --analysis-dir results/<analysis>
# summary.tsv: ki_reads/ki_pct, partial_reads/partial_pct (insert present but below the threshold), notes = every outcome class with its %
